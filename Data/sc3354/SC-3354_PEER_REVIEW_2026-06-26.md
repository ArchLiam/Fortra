# SC-3354 Peer Review — COLA Pricing: Renewal Quotes Not Priced Correctly

**Method:** read-only (sf data query, sf project retrieve, anonymous-Apex SOQL, sf apex run test — all roll back). Zero org mutation.

## 1. Verdict

### 🔴 NO-GO

**Single most important reason:** The SC-3350 NetUnitPrice seed — the only mechanism ever *proven* to commit the COLA-adjusted net to a non-derived license/subscription renewal line — was deleted from live when the co-owned `COLAUpliftPrehook` was reworked for SC-3346, and there is no surviving live mechanism that commits it. The result is confirmed in fresh live data: **9 of 9** post-rework non-maintenance renewal lines commit `NetUnitPrice = 0`/null, i.e. **Defect #1 reproduces at 100% on every renewal created since the rework.**

---

## 2. Headline regression — the SC-3350 seed was removed and defect #1 is back

**What happened (timeline, verified):**

- **2026-06-11 ~01:00Z** — SC-3350 fix deployed: a `COLAUpliftPrehook` seed that wrote `NetUnitPrice` directly inside an isolated `updateContextAttributes` batch (`buildNetUnitPriceUpdate` / `pendingNetUnitPriceUpdates`; log "SC-3350 submitting N NetUnitPrice seed updates"). Fix-version file carries `NetUnitPrice`×19, `seed`×5, `SC-3350`×7. This was the **only** path proven to flush the COLA'd net for non-derived renewal lines (a Formula/Assignment write to `NetUnitPrice` from a ListGroup does **not** commit; only `InputUnitPrice` sticks there — `NetUnitPrice` is engine/waterfall-backed).
- **2026-06-13/14** — The same class was reworked for a *different* ticket, **SC-3346** (renewal-MAINTENANCE pricing), realigned to a "v1.1" baseline (author Marc DeBrey; live `ApexClass.LastModifiedDate` 2026-06-14 by Liam Jeong). That rework **removed the SC-3350 net-seed entirely.**

**Live code state (re-verified against the live `ApexClass` body, byte-identical to the preflight retrieve):**
`COLAUpliftPrehook.cls` = 1378 lines, header `@version 1.1`. grep count = **0** for every seed marker: `NetUnitPrice`, `InputUnitPrice`, `buildNetUnitPriceUpdate`, `pendingNetUnitPriceUpdates`, `seed`, `SC-3350`. For license/subscription renewal lines, `buildItemUpdate` now writes **only** audit context attributes (`COLACalculatedPrice__c`, `Pre_COLA_Price__c`, `COLA_Source__c`, `COLA_Applied_Date__c`, `COLA_Solution_Category__c`). It never writes `NetUnitPrice` or `InputUnitPrice`.

**Does any other live mechanism commit the COLA net? No — and this is the crux where two upheld dimensions appear to disagree; they are reconciled by the fresh data:**

- Active pricing procedure = `Rev_Mgmt_Default_Pricing_Procedure` **V16** (the only Active version; V17/18/19 Inactive). V16 *does* contain a step **"COLA Uplift Net on Renewal"** mapping `COLACalculatedPrice__c → NetUnitPrice`, correctly gated to non-derived renewal lines (`ItemPricingSource='LastTransaction'` AND `DerivedPricingAttribute=false` AND `SalesTransactionActionType='Renew'` AND `COLA_Uplift_Percent__c IsNotNull`). The gate *is* satisfiable and the step *executes*.
- **D1** concluded this step is **INERT**: it lives inside `ListContainer2` (a ListGroup), the exact scope the 06-10/06-11 multi-agent live trace proved cannot flush a `NetUnitPrice` write — the proof being the in-container asymmetry (sibling `InputUnitPrice` write sticks; `NetUnitPrice` write does not). The identically-scoped V11 `SeedNetUnitPriceRenewal` was already proven inert.
- **D6** initially read this as the *working* commit path because the canonical 2-SKU audit quote prices penny-correct.

**Reconciliation (decisive):** D6's "penny-correct" quote `0Q0WC000003671t0AA` (Abstract net=4697.95, beSECURE net=929.25) is a **frozen residue** from the 06-11 Apex-seed run — `LastModifiedDate` 2026-06-13, never repriced since the seed removal. It is a stored value, not a freshly recomputed one. The **fresh** data (D2) settles the question: every non-maintenance renewal line created *after* the rework commits `NetUnitPrice = 0`/null. **The V16 ListGroup step does not flush net; the audit quote only looks correct because it was priced while the now-deleted Apex seed was live.** Both D1 and D6 verifications were upheld; the apparent conflict resolves entirely in favor of "no live commit mechanism," because the only positive evidence for V16 committing is a stale frozen value.

## 3. Defect status

### Defect #1 — renewal lines priced at $0/list instead of prior × (1 + COLA%) → **FAIL (blocker)**

Confirmed live in FortraUAT (read-only, 0 DML), independently reproduced by both the D2 author and the D2 verifier.

| Cohort | Result |
|---|---|
| Renew universe (all) | 59 lines: 57 Subscription + 1 Services (= 58 non-maint, SC-3350 scope) + 1 Renewal Maintenance (SC-3346 scope) |
| **Post-rework (CreatedDate ≥ 2026-06-12), non-maintenance** | **9 / 9 BROKEN** — 5 `NetUnitPrice=0`, 4 `NetUnitPrice=null`, **0 non-zero. 100% failure.** |
| Overall non-maintenance correct (`net == prior×(1+COLA%)`) | **15 / 58 = 26%** |
| Buckets (58) | ZERO 19 (33%) · CORRECT 15 (26%) · AT-LIST 10 (17%) · NET_NULL 7 (12%) · OTHER 5 (9%) · NET=CALC 2 (3%) |

The 9 broken post-rework lines **were priced** — COLA computed correctly into `UnitPrice`/`COLACalculatedPrice__c`; it simply never committed to net. Examples:
- beSECURE `0QLWC000003iZ0M4AU`: asset 6695.30 × 1.062 = **7110.41** in `COLACalculatedPrice__c`, `NetUnitPrice = 0.00`, `TotalPrice = 0.00`.
- EFT 8 Enterprise `0QLWC000003eofV4AQ`: 16868.40 × 1.0785 = **18192.57** computed, net = 0.
- OST `0QLWC000003g2uw4AA`: 9500 × 1.062 = **10089** computed, net = 0.
- Active Defense `0QLWC000003g4Ld4AI`: 94000 × 1.05 = **98700** computed, net = 0.

**Not a "drafts not yet repriced" artifact:** quote `0Q0WC0000039cfR0AQ` ("Renewal Quote") is **Status=Accepted, GrandTotal=$0.00**, created 06-15.

**The 26% "correct" rate is stale residue, not current behavior.** All 15 correct lines were created ≤ 2026-06-07 and last modified in the 06-11…06-13 seed window. Nothing created or repriced *after* the 06-14 seed removal is correct. The canonical audit quote `0Q0WC000003671t0AA` reads correct only because it is frozen; repricing it today on V16 yields $0. The dossier defect-#1 repro line `0QLWC000003bHpl4AE` is itself broken now (net=0, COLA pct/calc null).

### Defect #2 — Line Item Description not populated on renewal lines → **FAIL (high)**

Still reproduces live.

| Metric | Value |
|---|---|
| All renewals with Description populated | 24 / 59 = **40.7%** |
| Post-fix window (≥ 2026-06-11) renewals populated | 9 / 16 = 56.3% |
| **True failure rate** (attribute-bearing renewals still null) | **5 / 14 ≈ 36%** |
| Cohort comparison (post-fix) | regular Add 82.9% · Amend 78.6% · **Renew 56.3%** (renewals lag every cohort) |

**Root cause (mechanism):** `QLDescriptionGeneratorPrehook` (live `@version 8.0`, Active, 862 lines, api 65) is a passive pricing prehook with **zero renewal awareness** (grep `renew|QuoteAction|isRenewal` = 0) and **no self-triggered reprice**. It writes a description only when an external reprice happens to run a line through it. Proof: every populated renewal has `LastModifiedDate` strictly after `CreatedDate`; every genuine-null renewal has `LastModifiedDate == CreatedDate` (never repriced). Cleanest repro — four 06-24 beSECURE renewal lines with the full 4-attribute schema, on four different quotes; the one re-saved 48 min after creation got a description, the three never repriced stayed null (`0QLWC000003iWby4AE` / `0QLWC000003iWle4AE` / `0QLWC000003iXUo4AM` null; `0QLWC000003iZ0M4AU` populated). Renewal anchor `0QLWC000002UYeI4AW` still null (has 4 attrs = genuine failure); non-renewal anchor `0QLWC000003cIGm4AM` populated.

**Verifier correction (broadens, does not excuse):** the orchestration gap is **not renewal-specific** — sampled attribute-bearing regular-Add lines also ship null. The defect is wider than the renewal cohort; the renewal cohort still demonstrably lags (56.3% vs 82.9%). This strengthens the FAIL.
