## Stage 0 design (CORRECTED — important)
The original plan said extend `OrderSubmissionValidator` / `Order_Submit_Validation__mdt`. **That is WRONG / insufficient** (owner caught it):
- `OrderSubmissionValidator` fires ONLY on the manual **"Order Complete" quick action** (`Fortra_Order_Submission_Check` screen flow = validate + toast). It's bypassed by any headless/record-triggered submission → renewals slip $0 to Workday anyway.
- **Real Workday choke point = record-triggered on Order Update:**
  - `Order_After_Update_Platform_Events` (Update; entry `Workday_Sync_Status__c`→Pending) → **publishes `Order_Completed_WD__e`** (the Workday push).
  - `Order_Submission_to_Revenue_Orchestrator` (Update; entry `Status='Activated'`).
- **Correct hard block:** gate the `Order_Completed_WD__e` publish — suppress + hold when any OrderItem is renewal-maintenance & $0. Touches a load-bearing submission flow → **test carefully** (don't hold legit submissions).

**The $0 signal (read-only, use everywhere):** maintenance line = `Fortra_Product_Type__c LIKE '%Maintenance%'`, on renewal (`Quote_Type__c='Renewal'`), `Quantity>0`, **`UnitPrice<=0`/blank**. Use **`UnitPrice`** (the SC-3544 persisted stamp), **NOT `NetUnitPrice`** (runtime-only, non-null on just 9 rows org-wide). `Qty>0`+actionable-status deliberately excludes legit $0s (Qty-0 No-Change carryovers, 0%-COLA base>0, ~118K Won legacy-migration rows).

**Also keep (soft flag):** new `QuoteLineItem.Maintenance_Pricing_Failed__c` stamped after `Fortra_Quote_Reprice` — earliest signal, fires on the renewal path. (Manual `OrderSubmissionValidator` extension = optional rep-facing early warning, NOT the gate.)

## The problem (SC-3346), root cause
Maintenance is sold as **RNM** (`OneTime`, no term, never renewable) and renewed as a **different** product **RRM** (`TermDefined`). The swap defeats all three native RLM joins (exact `Product2Id` match, selling-model renewability, derived-pricing renewal exclusion), so the correctly-computed COLA net is **silently discarded**. `NetUnitPrice` is **engine-owned (`createable=false`)** — no Flow/DML/prehook/posthook can commit it. Native RLM would loudly block (`MissingContributor`); Fortra silently commits $0.

**Live impact (measured 2026-07-10):** 132,823 / 486,584 renewal-maint lines at $0 (27% all-time; 13/18 = 72% last 30d). Durable live-actionable backlog ≈ **7,203 unpriced lines / 687 accts** (the ~120K RRM $0 rows are 98.9% legacy noise).

**Endorsed fix = Path B:** model maintenance as ONE `TermDefined` `Product2`, sold+renewed as the exact same `Product2Id` (`Type=Renew`, `PricingSource=LastTransaction`), priced by **native uplift** — retiring the RNM→RRM swap and the entire custom COLA stack.

## The false-green trap (do NOT fall for this)
Path B is **~70% built and deployed to UAT at near-full scale**: 1,681 TermDefined maint PSMOs + 33,620 PBEs (`RenewalMaintenanceCatalogProvisionBatch` + `RenewalMaintenanceProvisionService`), **untracked in git**. BUT **31,016 / 33,620 mirror PBEs are `UnitPrice=0`**, and only **ONE** line (**BoKS `76.57`**) is proven end-to-end. **A renewal-$0 count dropping to 0 is NOT proof** — the Renew line can resolve the $0 list PBE instead of `LastTransaction` prior net and re-create the defect invisibly. **Validate strictly on committed NET** (never `UnitPrice`, never `PBE.UnitPrice=$0`; `null==null` is UNTESTED, not PASS).
