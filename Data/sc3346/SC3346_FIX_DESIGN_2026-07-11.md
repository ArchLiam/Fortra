# SC-3346 Go-Forward Fix Design — Renewal-Maintenance Net Commit (non-partner, USD)

*Finalized 2026-07-11. Root cause verified live; design adversarially reviewed; premise corrected twice (see §1). Build spec for staged execution — Stage 0 buildable now, later stages gated.*

---

## 1. Corrected root cause (supersedes "hardcoded to BoKS")

Two earlier framings were **wrong** and are corrected here:

1. **NOT a BoKS-hardcoded coverage gate.** The BoKS constants (`BOKS_PERPETUAL_PRODUCT_CODE`, `RENEWAL_MAINTENANCE_PRODUCT_CODE`) live only in `RenewalMaintenanceAutoAddHandler.ensureRenewalMaintenancePresent` — **dead code** (zero non-test callers; class header: "Production trigger path no longer calls this handler"). The live net-committer is **`RenewalMaintenanceProvisionService.provision`**, chained in `RenewalAssetQuantityQueueable.execute:17`, and its selector is **product-agnostic** (`Fortra_Product_Type='New Maintenance'` + OneTime PBE + `QuoteAction.SourceAssetId` — no SKU list).

2. **The net commits via the CUSTOM COLA stack, NOT native derivation.** Verified on the BoKS canary (`0Q0WC000003KC6X0AW`): the committed maint line carries `COLA_Source__c='CMDT Lookup'`, `COLA_Applied_Date__c` stamped, `Pre_COLA_Price__c=71` (asset price), `UnitPrice=71×1.0785=76.5735 → NetUnitPrice 76.57`. The committing TermDefined PBE (`01uWC000007EEIQYA4`) has **no PricebookEntryDerivedPrice row**, so native derivation was impossible. The commit is the **SDD-documented `COLAUpliftHandler` before-insert `UnitPrice` write on a `Renew` priced node** — a supported path, *not* the Do-Not-listed `updateContextAttributes`-on-a-non-priced-node write (which is what gets discarded).

**Actual root cause of the residual $0 (go-forward):**
- **(a) RELIABILITY** — `provision` runs async inside `RenewalAssetQuantityQueueable` with **no try/catch and silent skip/`continue` guards**. Any throw, race (two after-insert queueables), single-job-budget exhaustion, or missing PBE leaves the raw `No Change / OneTime / Qty 0 / $0` carryover, which reprice cannot rescue. This is the intermittent-drop class (proven on quote `0Q0WC000003Jlj30AC`).
- **(b) CATALOG DATA** — of active New-Maintenance products with a USD TermDefined-Annual PBE, **674 have that PBE as `IsDerived=false` + `UnitPrice=0` ($0-mirror)** vs 1,043 usable. `provision` swapping onto a $0-mirror can produce a **silent $0** ("succeeds", still $0).

**What is NOT the cause:** the 536K May-2026 "Service Data Migration" backlog (Won/Approved historical, never engine-priced) — data hygiene, not an engine defect. Genuine engine-priced renewals commit (proven: BoKS via `initiateRenewal` / flow / amend, all 76.57).

## 2. Provenance of the mechanism (why the design lands where it does)

`provision`'s real job is **to make the maintenance line a TermDefined `Renew` priced node** (swap PBE, mint `Renew` QuoteAction sourcing the exact asset). The **net then comes from the asset price** via the COLA stack (`Pre_COLA_Price = Asset.Price`, `× (1+COLA)`), *not* the PBE. Therefore a $0 PBE `UnitPrice` is **not automatically fatal** (the BoKS PBE was itself `UnitPrice=0` and committed). The narrowed open risk: the 674 mirrors are `IsDerived=false`, and the COLA renewal gate may require `IsDerived=true` — **the single thing the non-BoKS POC must test.**

## 3. The fix — two workstreams

### Workstream 1 — RELIABILITY (code; safe; buildable now)
Make every drop **loud** and add a **backstop**, without changing the swap logic.

- **B3 — surface the silent skip.** In `provision`, split the `continue` (`:59-61`): when a carryover is skipped because **no TermDefined-Annual PBE resolves** (`termDefinedPbeId == null`), publish a `Pricing_Exception__e` (`Severity__c='Warning'`) naming `product|book|currency`. (Do NOT warn on the benign "already-exists" skip.) → turns the 674-mirror / missing-PBE coverage gap into a visible signal. **[STAGE 0 — this increment]**
- **B2 — try/catch + telemetry** on the async execute (today `RenewalAssetQuantityQueueable.execute:13-18` has none): wrap → `ExceptionLogger.safePublish(new Pricing_Exception__e(Severity__c='Error', Source__c='RenewalMaintenanceProvision', Hook_Phase__c='async-provision', Context_Id__c=quoteId, Message__c=...))`. **[STAGE 1]**
- **B1 — consolidate the two racing after-insert queueables** (`QuoteLineItemTriggerHandler.afterInsert:69-70`) into one ordered `RenewalPostPersistOrchestrator` (qty → **provision** → cleanup → dedupe) so the DELETE never races ahead of the swap; preserve `RenewalMaintenanceProvisionService.bypass` and the New-Maintenance→Amend branch (`RenewalAssetQuantityHandler:107-124`, SC-3412/3413). **[STAGE 3 — RISKIEST; gated; adjacent to SC-3368/3412/3413 regressions]**
- **C — sweeper backstop.** Scheduled `RenewalMaintenanceSweepBatch`: find renewal quotes **not yet ordered** whose maint line is still `$0` (key off the **persisted `UnitPrice`** stamp — `NetUnitPrice` is runtime-only/unqueryable), Warning + (later) re-run `provision`. Idempotent; scoped to Draft/not-ordered only (never Approved/Won/Ordered). **[STAGE 4]**

### Workstream 2 — CATALOG DATA (data; separate, gated)
Remediate the **674 `$0`-mirror** TermDefined-Annual PBEs (make derived or priced) via `RenewalMaintenanceCatalogProvisionBatch` / the Bulk-PBE tool. Gated, reversible, validated on committed net. **Prereq for full non-BoKS coverage — not a code dependency for Workstream 1.**

### Anti-false-green guard (non-negotiable, spans both)
No success gate — build, test, canary, rollout — may go green on a silent $0. Enforced by B3 (missing-PBE Warning) + the sweeper's still-$0 detection. **Validate only on committed `NetUnitPrice`**, never `UnitPrice`/`PBE.UnitPrice=0`.
