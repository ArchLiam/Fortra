01 — The problem in one paragraph

What's actually broken

A renewal line commits its price only when it renews as a priced Renew node — which requires the owned asset to be a TermDefined subscription. Subscriptions do this and commit cleanly ($9.11M of healthy renewal net across the working population). Maintenance does not: it is sold as a OneTime RNM product, so on renewal the platform routes it to Amend (a OneTime asset has no term to renew), the line falls into the derived pricing path — which the procedure deliberately excludes from renewals — and the net is never committed. It lands null / $0.

Because the platform can't price it, roughly a dozen Apex hooks, two competing renewal engines, and ~197 near-duplicate configuration rules were layered on to force the number back in. That accreted stack — not the missing number — is the real cost.

04 — Root cause

One modeling choice defeats three native joins

Native RLM assumes one lifecycle-managed TermDefined asset per subscription, renewed as itself. Fortra's two-catalog maintenance split breaks all three native mechanisms simultaneously — which is why no single patch has ever been enough.
join 1

Asset ↔ line match

Native Asset Discovery matches Asset.Product2Id = line.Product2Id exactly. An RNM asset never matches an RRM line. First renewal finds no source.

join 2

Selling-model renewability

Renewability is immutable and derived from the selling model. OneTime → no term → no LifecycleEndDate → not renewable. Can't be conferred later; the fields are read-only.

join 3

Derived pricing on renewals

The procedure's DerivedProductsNonRenewal filter strips derived lines from renewals — correctly, per native intent. So a derived maintenance line has no pricing home on renewal at all.

The platform is explicit: there is no "renew as a different product."

Salesforce's own taxonomy treats "become a different product" as a Swap / Upgrade — an amendment, never a Renew. initiateRenewal has no input to renew an asset as a different Product2. The RNM→RRM pattern is off-platform by construction, which is exactly why it needs custom cross-product stamping to work at all.

06 — The gap

Native intent vs. what's built

Native RLM — designed
  • One TermDefined asset per subscription, renewed as itself (Product2Id matches every cycle).
  • QuoteAction engine-assigned from the selling model; SourceAssetId carries provenance.
  • Renewal price = PricingSource (LastTransaction or ListPrice) — the only two sources.
  • Uplift = PriceRevisionPolicy + UnitPriceUplift, config-driven.
  • Asset updated in place by createOrUpdateAssetFromOrder.
  • Missing contributor → hard validation error, never a silent null.
Fortra — as built
  • Two catalogs (RNM/RRM), paired only by naming convention; ~114K parallel assets.
  • QuoteAction manually synthesized cross-product by account|Solution_Category__c.
  • Renewal price carried by an out-of-band Apex fossil-reconstruction chain.
  • Uplift = custom COLA stack; native fields unused.
  • Renewal spawns a new asset on a successor contract; both stay active.
  • Missing source → silent NetUnitPrice=null.
07 — Re-architecture

Target state, and how we get there

North star: collapse maintenance to a single TermDefined product that renews as itself — priced by PricingSource=LastTransaction and native uplift, with the asset updated in place. That one move fixes the null-net defect, retires the two-catalog split, and unlocks native pricing so the entire COLA stack can be deleted.
The hard constraint that shapes the sequencing

Existing OneTime RNM assets are immutable — they can't be made renewable, and native renewal can't swap them to RRM. So the installed base (752+ accounts) needs a bridge during transition, while go-forward sales adopt the clean model. That bridge already works.

Phase 0
✓

Bridge the installed base proven live

The born-net RenewalQuoteActionStamp — mints a Renew QuoteAction sourcing the owned RNM asset cross-product, so the line is priced from birth. Committed 76.57 on the first line that has ever committed in this investigation.

  • Keep it as the transition mechanism for the ~22.8K legacy RNM assets — they'll age out as their maintenance re-provisions under the new model.
  • Finish the rollout: reprice the live backlog (7,202 lines) through the born-Renew path.
Phase 1
1

Collapse the maintenance catalog

Model maintenance as one TermDefined product per line, sold and renewed as itself. Retire the RNM→RRM swap for new business.

  • Flip the 100 active RRM products missing a TermDefined default (incl. 7 real FIM SKUs) and the 39 inverted RNM defaults.
  • New maintenance sale → born TermDefined → renews on native Product2Id match every cycle, no stamp needed.
  • Add an explicit product-pair / lineage field for the transition window (naming convention + coarse Solution_Category is not a 1:1 key).
Phase 2
2

Adopt native renewal pricing

Replace the custom COLA stack with PricingSource=LastTransaction + PriceRevisionPolicy (Flat, keyed by Region↔Solution Category) + UnitPriceUplift — the fields already in the org.

  • Retire COLAUpliftHandler, COLAUpliftPrehook, RenewalMaintenancePricingService, and the duplicated calculators.
  • Migrate the 21 COLA_Uplift_Rules__mdt rows → PriceRevisionPolicy records (capability-preserving; unlocks CPI later).
  • Collapse the 4-writer commit chain to the native pricing pass.
Phase 3
3

Consolidate the automation

One renewal engine, one enrichment path, one commit — and delete what's dead.

  • Pick Model B; retire the legacy ContractLineItem engine and the redundant enrichment flow.
  • Consolidate maintenance auto-add onto one mechanism (retire ~197 duplicate PCRs + the dead Apex fallback).
  • Delete confirmed dead code; dedupe the numbered procedure clones; give the 6-handler trigger an explicit ordered dispatcher.
  • Fix succession to set Status='Renewed' and stop keying downstream logic on the always-blank Order.Type.
Why this order

Phase 0 stops the bleeding today. Phase 1 is the pivot — every later simplification depends on maintenance being TermDefined. Phases 2–3 are then deletions: once maintenance renews natively, the COLA stack, the second engine, the duplicate rules, and the fossil-reconstruction chain all become removable rather than maintainable. The re-architecture is measured in code deleted, not added.
