Legend — what each verdict means & why

PASS
V21 priced the scenario correctly AND it was proven.
The seed passed preflight, the intended branch fired on valid inputs, and the measured numbers matched the expected behavior on real data. A PASS is confirmed-correct behavior, never static reasoning.
FAIL
V21 produced the wrong number on valid, preflighted input with the intended branch confirmed to have run.
The fault is in the procedure or in org config a real user would also hit — not in the test data. Every FAIL survived an adversarial ‘prove it isn’t a data issue’ challenge. Sub-classed PROCEDURE-DEFECT vs ORG-CONFIG-DEFECT.
BLOCKED
Could not be smoke-tested to a trustworthy verdict — deliberately NOT scored as FAIL.
Caused by an environment gap (no Evergreen catalog, no contracted lines in UAT), a headless-insert $0 fixture artifact, stale/malformed seed data, or another unprovable input. An unproven input must never be reported as a procedure defect; when in doubt we suspect the fixture, not V21.
Root-cause classes (applied to FAIL / corrected scenarios)
PROCEDURE-DEFECT Inputs valid, intended branch ran, V21 produced the wrong number — a procedure/engine fault.
ORG-CONFIG-DEFECT Wrong number traces to missing/incorrect config a real UI user would also hit (e.g. a product genuinely lacking a required pricing attribute, or a currency-incomplete decision table).
TEST-DATA-ARTIFACT The fixture was malformed / the branch never ran / a stale field — not a V21 fault. Reclassified to BLOCKED, not a reportable defect.
EXPECTATION-ERROR The catalog’s expected value was itself wrong. Corrected and re-graded to PASS.

Headline findings

Currency cluster (3 defects, P0)
G-01 / G-02 / J-10 — configured & derived pricing is currency-blind: an EUR line picks up the USD ABA override (G-02), the Unit-Price-Display step double-applies FX (G-01), and EUR derived-maintenance prices $0 because the IsDerived flag exists only on the USD PBE (J-10). All trace to SC-3384.
Null-unsafe filter hard-crash (2 defects, P0/P1)
K-01 (cancellation) and F-12 (mid-term amend-remove) both abort the ENTIRE reprice at StampBaseFilter (SF-BRE-00004) because criterion ‘NetUnitPrice > 0’ has no IsNull guard — 3 of 6 instances remain unpatched. No credit is produced. SC-3441.
New regression from today’s in-place edit (P1)
F-09 — non-USD partner lines are now double-FX-converted (corporate rate × hardcoded rate), understating net ~8%. This same quote PASSed in run-1 at 01:47Z and FAILs after the 05:56Z in-place V21 edit — a confirmed regression.
Discount compounds across reprices (P0)
H-01 — the manual line-level amount discount seeds its base from NetUnitPrice instead of ListPrice, so the discount re-applies on every reprice and net erodes (45000 → 40500 → …). Same family as the F-07/E-03 idempotency fixes, which didn’t cover the manual-amount path.
Derived / maintenance config gaps (P0–P2)
J-06 partner band uses license 15% not New-Maint 12%; J-09 derived lines with no PBEDP row price silently null (only 199/1889 IsDerived PBEs covered); A-07 ~1497 maintenance products lack the Maintenance-Type attribute → $0/100%-copy. SC-3346/3359/3372.
What got better since the last run
5 prior FAILs are fixed (F-03, G-04, I-01, K-09 + K-02 expectation); 9 more prior FAILs were correctly downgraded to BLOCKED — they had been logged on headless-insert $0 artifacts or env gaps, not real V21 faults.
How this was tested. Every scenario was smoke-tested on real FortraUAT data (find/reuse a real record → mandatory preflight gate → headless Force-reprice through live V21 → re-measure actual field values), not statically reasoned. Findings ran a 4-stage adversarial pipeline: (1) 104 executor agents, (2) an independent verifier on every FAIL, (3) a skeptical data-artifact audit that defaulted each FAIL to “bad seed data” until disproven, and (4) an Opus tie-breaker on every verifier-vs-audit conflict, each resolved against a decisive live fact. 154 agents, ~8.9M tokens.

Data discipline. No FAIL was allowed to stand as a defect until its seed passed preflight and the explainability trace confirmed the intended V21 branch ran on valid inputs. The audit + tie-breaker caught 3 false-positive defects (stale data, malformed EndDate, wrong QuoteAction binding), corrected 2 catalog expectation-errors, and rescued 1 real defect a verifier had wrongly dismissed. Validation only — fixes are PROPOSED, not applied.

Data & expectation corrections — what the adversarial audit + tie-breaker caught

These are the scenarios where the first-pass FAIL did not survive scrutiny — proof that the run distinguishes a malformed fixture from a real procedure fault.

D-09 False defect caught FAIL (PROCEDURE)  →  BLOCKED (TEST-DATA-ARTIFACT) via tie-breaker (sided with the data-audit)
Live EUR FX is 0.92 (CurrencyType + DatedConversionRate since 2026-02-13); the cited 1268.44 implies 0.9346, which exists nowhere in the org. UnitPrice stayed FROZEN across 3 fresh reprices while the net mutated — a stale persisted field, not a live V21 output. A clean reprice yields 1357.2 × 0.92 = 1248.62 (PASS). The genuine currency-idempotency concern is already captured by G-01/G-02.
I-02 False defect caught FAIL (claimed)  →  BLOCKED (TEST-DATA-ARTIFACT) via tie-breaker (sided with the main verifier)
Two identical TermDefined lines differ only in EndDate; the disputed line’s null PTC is caused by a malformed off-by-one EndDate (2027-06-29 vs the org convention StartDate+1yr−1day = 2027-06-28). A clean control with the correct EndDate gets PTC=1 on the current V21 — the mechanism works on valid lines.
J-05 False defect caught FAIL (claimed)  →  BLOCKED (TEST-DATA-ARTIFACT) via tie-breaker (sided with the main verifier)
The ‘missing-net’ line kbxJ is bound to a QuoteAction of Type=‘Amend’, not Renew (the only Renew-bound line is kbxK). A null net on an amend-no-change line is by-design, not a COLA-commit failure — the fixture used the wrong QuoteAction binding.
K-02 Expectation corrected FAIL (claimed)  →  PASS (EXPECTATION-ERROR) via data-audit
The catalog expected a ‘MissingContributor’ surfacing that requires step SurfaceMissingContributorK02 — which exists only in the V22 Draft, not the active V21. A null net on a lone derived line with no contributor is the documented, owner-accepted SC-3346/SC-3372 ‘no priced node’ behavior. The catalog graded V21 against an un-deployed enhancement.
K-10 Expectation corrected FAIL (claimed)  →  PASS (EXPECTATION-ERROR) via data-audit
The catalog expected ALE=14000 (negative line excluded). But Quote.ALE__c is a Formula(Number) literally = ‘Subtotal’, so a correctly-priced Qty=−1 credit MUST roll into ALE. V21 yields Subtotal=ALE=11200 = 14000 + (2800 × −1) — arithmetically correct, no NPE, positive line uncorrupted.
I-03 Real defect rescued BLOCKED (verifier dismissed)  →  FAIL (PROCEDURE-DEFECT) via tie-breaker (sided with the data-audit)
The main verifier dismissed I-03 as a data artifact (‘no writer / wrong field / stale’). The tie-breaker disproved that on live data: a CLEAN list-priced TermDefined line with PTC=0.7397 comes out full 750 on BOTH NetTotalPrice and TotalLineAmount; only the adjustment path prorates. The defect is real — now reported.
