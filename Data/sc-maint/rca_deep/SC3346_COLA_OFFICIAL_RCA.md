# How COLA / Renewal / Derived Pricing Populates NetUnitPrice — Official Mechanism vs Our Defect

*Audience: build owner (Liam) · Context: SC-3350 / SC-3346 / SC-3404, renewal-maintenance line `PIA-PIA-RRM-PIAM` on a maintenance-only renewal quote, derived PBE (`IsDerived=true`, `ListPrice=0`), `Rev_Mgmt_Default_Pricing_Procedure`, native `DerivedProductsRenewals` element.*

---

## Executive answer

Per official Salesforce docs, a **derived renewal line has no price of its own** — its `NetUnitPrice` is an **engine output**, written *only* by the Derived Price element when a **contributor** has been resolved into the shared pricing context by an upstream **discovery procedure** ([Trailhead — Implement Derived Pricing](https://trailhead.salesforce.com/content/learn/modules/advanced-price-management-with-revenue-cloud/implement-derived-pricing); [Help — Discovery procedure for pricing](https://help.salesforce.com/s/articleView?id=sf.pricing_discovery_procedure_for_pricing.htm&language=en_US&type=5)). For a **renewal** line the contributor is the **prior ASSET being renewed** (its latest `AssetActionSource` / Last-Transaction-Price), reached through `QuoteAction(Type='Renew').SourceAssetId` set by `initiate-renewal` — **not** a license/contributor *line* on the quote ([Object Reference — QuoteAction](https://developer.salesforce.com/docs/atlas.en-us.object_reference.meta/object_reference/sforce_api_objects_quoteaction.htm); [Help — CPI & price uplifts](https://help.salesforce.com/s/articleView?id=ind.qocal_consumer_price_index_and_price_uplifts.htm&language=en_US&type=5)). Our line is wrong (60.64 fossil or $0, never the correct 67.38) because the **contributor never resolves correctly**: lines with no `QuoteAction` resolve *no* asset → the element is skipped → the persisted "born" 60.64 double-discount fossil survives; lines whose `SourceAsset` points at the wrong product (the owned New-Maintenance `PIA-PIA-RNM-PIAMBK` asset) resolve a contributor that has no usable LTP/AAS for this derived product → the formula yields $0. The documented remedy is therefore to **fix the contributor (the source asset and its presence in context), not to write `NetUnitPrice`** — which is read-only to DML and engine-owned, so our COLAUpliftHandler/posthook/`RenewalMaintenancePricingService` writes return `isSuccess=true` but never move a settled derived line.

## The official mechanism, step by step

Renewal action → contributor → derived pricing → `NetUnitPrice` commit. Each step is tagged **[documented]** (verbatim official quote) or **[inferred]** (combining two documented mechanisms; must be confirmed against the live procedure/FINEST trace).

**Step 0 — The asset must carry renewal intent.** `[documented]` The renewing Asset must have Renewal Term, Renewal Term Unit, and Renewal Pricing Type before renewal. `Renewal Pricing Type` selects the basis: *"To renew at the same price, use Last Negotiated Price. To renew at the current list price, use List Price."* ([Subscription Management — Renew](https://developer.salesforce.com/docs/revenue/subscription-management/guide/solution-renew.html)). Amend/Renew/Cancel **only work on assets created through the standard lifecycle (order activation)** — *"Amend, Renew, and Cancel operations work only with assets that were created through the standard Agentforce Revenue Management lifecycle (order activation)"* ([Help — Manage assets in RLM](https://help.salesforce.com/s/articleView?id=ind.qocal_manage_assets_in_revenue_lifecycle_management.htm&language=en_US&type=5)). Migrated/manually-created assets may lack the data relationships, so the renewal cannot establish the contributor link.

**Step 1 — initiate-renewal off a specific asset.** `[documented]` *"Call /asset-management/assets/{assetId}/actions/initiate-renewal to create a renewal order, passing in the ID of the updated asset. Subscription management creates a renewal order with a renewal order item, with the order item's total line amount calculated accordingly"* ([Subscription Management — Renew](https://developer.salesforce.com/docs/revenue/subscription-management/guide/solution-renew.html)). The renewal output is generated **by the platform from the source asset**, asynchronously (`AssetRenewInitiatedEvent` carries the new order ID — [Dev Guide — Renew assets action](https://developer.salesforce.com/docs/atlas.en-us.revenue_lifecycle_management_dev_guide.meta/revenue_lifecycle_management_dev_guide/actions_obj_renew_assets.htm)).

**Step 2 — The renewal line is keyed to the asset, not a sibling line.** `[documented]` `QuoteAction.Type` valid values include `Renew`; `QuoteAction.SourceAssetId` is *"The asset changed by this sales transaction"* — for a renewal, the prior asset being renewed. There is **no `QuoteLineItemId` on QuoteAction** — it is keyed to the **Quote and the SourceAsset** ([Object Reference — QuoteAction](https://developer.salesforce.com/docs/atlas.en-us.object_reference.meta/object_reference/sforce_api_objects_quoteaction.htm)). This is exactly what our `COLAUpliftHandler` keys off (Type='Renew' + SourceAsset), consistent with the object's design.

**Step 3 — Discovery procedure resolves the contributor into the shared context.** `[documented]` Before the pricing procedure runs, a **discovery procedure** gathers data from three sources — **Products**, **Assets** (*"Information about products the customer already owns"* — original price, quantity, active contract period), and **quote headers** — and *"The collected data is then written into a context definition, which serves as a structured repository of contributing factors"* ([Help — Discovery procedure for pricing](https://help.salesforce.com/s/articleView?id=sf.pricing_discovery_procedure_for_pricing.htm&language=en_US&type=5)). Its three elements: **Fetch Pricing Rules** (locates the derived price record), **Map Products** (identifies SOURCE→DERIVED product mapping), **Asset Discovery** (*"provides awareness of a customer's existing products or services"*) ([Help — Discovery procedure for pricing](https://help.salesforce.com/s/articleView?id=sf.pricing_discovery_procedure_for_pricing.htm&language=en_US&type=5); [Trailhead — Explore Derived Pricing & Discovery Procedures](https://trailhead.salesforce.com/content/learn/modules/advanced-price-management-with-revenue-cloud/explore-derived-pricing-and-discovery-procedures)). **Hard requirement:** *"To make sure derived pricing works, always use the same context definition in both your discovery procedure and your pricing procedure"* ([Help — Discovery procedure for pricing](https://help.salesforce.com/s/articleView?id=sf.pricing_discovery_procedure_for_pricing.htm&language=en_US&type=5)). The asset reaches the engine via the `SalesTransactionContext`, which *"link[s] sales transactions to objects like Quotes, Assets, and Orders, connecting them to pricing nodes"* ([Dev Guide — Pricing overview](https://developer.salesforce.com/docs/atlas.en-us.revenue_lifecycle_management_dev_guide.meta/revenue_lifecycle_management_dev_guide/pricing_overview.htm)).

**Step 4 — Derived Price element computes & commits NetUnitPrice.** `[documented]` *"Derived Pricing always derives the Net Unit Price of the derived product... the Derived Price element calculates the product's derived price using the formula from the derived price record and the data gathered by the discovery procedure"* ([Trailhead — Implement Derived Pricing](https://trailhead.salesforce.com/content/learn/modules/advanced-price-management-with-revenue-cloud/implement-derived-pricing)). Its inputs are all **Contributor*-keyed**: `Contributing Net Unit Price`, `Contributing Sub Total`, `Contributing Source`, `Contributing Scope`, `Contributor`, `Contributing Product`, `Header Total` — output is the derived product's **Net Unit Price** ([Trailhead — Implement Derived Pricing](https://trailhead.salesforce.com/content/learn/modules/advanced-price-management-with-revenue-cloud/implement-derived-pricing)). This is the public analog of our native `DerivedProductsRenewals` element, whose input params (`ContributingNetUnitPrice`, `ContributingId`, `ContributingProduct`) match this list 1:1.

**Step 5 — The renewal price value itself comes from the asset's LTP, uplifted by CPI/COLA.** `[documented]` *"If the asset's pricing source is last transaction price (LTP) and uplift type is CPI/Variable, the net unit price is calculated as the latest asset action source (AAS) change in subtotal divided by the change in quantity \* (1 + the renewal uplift percent)"* ([Help — CPI & price uplifts](https://help.salesforce.com/s/articleView?id=ind.qocal_consumer_price_index_and_price_uplifts.htm&language=en_US&type=5)). Worked example: an LTP of $150 → `$150 × (1 + CPI + Renewal Uplift)`. The `AssetActionSource` is the registry the pricer reads — *"an optional way to record what transactions caused changes to lifecycle-managed assets... used to trace financial... information about asset actions"* ([Dev Guide — AssetActionSource](https://developer.salesforce.com/docs/atlas.en-us.revenue_lifecycle_management_dev_guide.meta/revenue_lifecycle_management_dev_guide/sforce_api_objects_assetactionsource.htm)). Reps may *"apply an additional discount on top of the calculated price uplift, overriding the net unit price"* — an explicitly supported override path ([Help — CPI & price uplifts](https://help.salesforce.com/s/articleView?id=ind.qocal_consumer_price_index_and_price_uplifts.htm&language=en_US&type=5)).

**The one inferred join.** `[inferred]` The official docs describe the renewal price at the **asset/AAS level** and the derived-pricing **contributor framework** *separately*. The claim that *"`DerivedProductsRenewals` reads the renewed asset's AAS/LTP as its `Contributing*` inputs"* is the bridge between those two documented mechanisms. It is strongly implied (Asset Discovery exists precisely to surface owned assets as contributors; the asset is a documented contributor *source*), but the docs do **not** name `DerivedProductsRenewals` or state that `ContributingId` can be an Asset/AAS rather than a sibling line. **Confirm against the live element's input bindings and a FINEST reprice trace before relying on it for a fix.**

## The "contributor" — what it officially is, what must be in context, and how QuoteAction/SourceAsset/initiateRenewal feeds it

**What it is.** `[documented]` A contributor is the **source from which a derived price is calculated** — and it is **not required to be a line on the quote**. Salesforce derives *"a product's price based on the price of another product, **asset**, or the overall quote"* ([Trailhead — Explore Derived Pricing & Discovery Procedures](https://trailhead.salesforce.com/content/learn/modules/advanced-price-management-with-revenue-cloud/explore-derived-pricing-and-discovery-procedures)). On the data model, `PriceBookEntryDerivedPrice.ContributingProductId` is the *"Source product from which the derived price is calculated... derived from another source such as a product or an asset"* ([Dev Guide — PriceBookEntryDerivedPrice](https://developer.salesforce.com/docs/atlas.en-us.revenue_lifecycle_management_dev_guide.meta/revenue_lifecycle_management_dev_guide/sforce_api_objects_pricebookentryderivedprice.htm)). Spring '25 formalized the term: *"Accurately Calculate Derived Prices with Pricing Contributors"* — fetched by discovery procedures ([Release Notes — Pricing contributors](https://help.salesforce.com/s/articleView?id=release-notes.rn_pricing_fetch_pricing_contributors_using_discovery_procedures.htm&language=en_US&release=250&type=5)).

**For a renewal, the contributor is the prior ASSET.** `[documented + inferred]` This is the single most important correction to the original framing. A maintenance-only renewal quote **does not need a license/contributor line present** — it needs the correct **source asset** resolved into context. The chain is:

```
initiate-renewal(assetId)  →  QuoteAction(Type='Renew').SourceAssetId = that asset   [documented]
        ↓ (Asset Discovery, discovery procedure)
   Asset's original price/qty/contract + AssetActionSource (LTP)  →  written to shared context   [documented]
        ↓
   Derived Price element reads ContributingNetUnitPrice/ContributorProduct  →  formula → NetUnitPrice   [documented mechanism; asset→Contributing* mapping is inferred]
```

**Contributor Scope is the load-bearing switch.** `[documented concept / inferred exact values]` `ContributorScope` determines **where** the contributor is found: *transactional* = current quote lines only; *non-transactional* = existing customer **assets**; or *both*. For a maintenance-only renewal with **no license line on the quote**, a contributor can resolve **only if scope includes non-transactional (asset) lookups** and Asset Discovery returns the correct prior asset. (The picklist exists and is named on the Implement-Derived-Pricing config page; the exact verbatim enumeration of its values did not render — confirm the value our element uses.)

**What must be present in context for our line to price correctly:**
1. A `QuoteAction(Type='Renew')` whose `SourceAssetId` = the **correct** `PIA-PIA-RRM-PIAM` (Renewal-Maintenance) asset. `[documented role of the field]`
2. That asset created through the **standard lifecycle** with `Renewal Pricing Type` = Last Negotiated/Last Transaction Price and a populated `AssetActionSource` carrying the prior net. `[documented]`
3. The discovery and pricing procedures sharing **one context definition**, with `ContributorScope` admitting **non-transactional/asset** lookups, and `Map Products` mapping that asset's product → the derived `PIA-PIA-RRM-PIAM` product. `[documented requirement; the Map-Products product-equality detail is inferred]`

## Why OUR line commits 60.64 / $0 (not 67.38) — mapped to the official mechanism

The three observed outcomes map cleanly onto **contributor resolution success/failure**, which is exactly what the official mechanism predicts:

| Observed line | Contributor state (official lens) | Mechanism | Result |
|---|---|---|---|
| **67.38 (correct)** — Type='Renew' QuoteAction, SourceAsset = **real `PIA-PIA-RRM-PIAM`** asset | Valid contributor resolves: Asset Discovery surfaces the right Renewal-Maintenance asset + its LTP/AAS | Derived Price element gets `ContributingNetUnitPrice`/`ContributorProduct`; formula evaluates `LTP × (1+CPI+uplift)` and commits | **Documented happy path** — asset-as-contributor, non-transactional scope |
| **$0** — SourceAsset = **wrong product** (owned New-Maintenance `PIA-PIA-RNM-PIAMBK`) | Contributor resolves to the **wrong product**: `Map Products` does not match the derived line's expected source, or the asset has no LTP/AAS mapping to this derived PBE | Formula operates on an empty/zero contributor → degenerate output | `[documented mechanism; the $0-vs-error specific is inferred]` |
| **60.64 fossil** — **no QuoteAction** | **No contributor at all**: nothing for Asset Discovery to follow, so nothing is written to context | The contributor-keyed Derived Price element has no input → **effectively does not write** → line keeps its persisted/born value | `[documented: discovery must supply contributor; skip-retain behavior inferred from our logs]` |

This is precisely your finding that **`DerivedProductsRenewals` is the only element that commits `NetUnitPrice` on a derived line, and is skipped when no contributor resolves**. The 60.64 is the pre-fix double-discount value that was *persisted onto the line at birth* and never overwritten because the element never fired.

**Why DML and reprice-time Apex writes don't stick.** `[documented]` `NetUnitPrice` is an **engine output**, not a free-writable field. *"Derived Pricing always derives the Net Unit Price"* (engine-owned, [Trailhead — Implement Derived Pricing](https://trailhead.salesforce.com/content/learn/modules/advanced-price-management-with-revenue-cloud/implement-derived-pricing)); pricing changes on derived/renewal lines are produced by the engine and **recorded as `QuoteLineDetail`** — *"Revenue Cloud generates QuoteLineDetail records to capture pricing and quantity changes, including derived pricing or repricing during an amendment and early renewals"* ([Dev Guide — QuoteLineDetail](https://developer.salesforce.com/docs/atlas.en-us.revenue_lifecycle_management_dev_guide.meta/revenue_lifecycle_management_dev_guide/sforce_api_objects_quotelinedetail.htm)). So:
- DML insert of `NetUnitPrice` does not take → field is engine-assigned, not createable on a derived QLI. `[documented framing; hard read-only flag is inferred — confirm via describe]`
- Posthook / custom committer / `RenewalMaintenancePricingService` writes return `isSuccess=true` but don't move a **settled** derived line → the value is set **only** when the derived element fires with a resolved contributor at reprice; a settled line whose contributor never resolved is simply never re-touched. `[inferred from our logs + documented engine-ownership]`

Your `COLAUpliftHandler` writing **`UnitPrice`=67.38** before-insert computes the correct *intended* value into a custom field, but `UnitPrice` ≠ the engine-committed `NetUnitPrice`; without a resolved contributor, the derived element never converts that intent into the committed `NetUnitPrice`.

## What is REQUIRED to populate NetUnitPrice correctly — ranked by documentation support

**Option A — Resolve the correct asset contributor into context (the documented happy path). `[BEST SUPPORTED]`**
Make every renewal-maintenance line carry a `QuoteAction(Type='Renew')` whose `SourceAssetId` = the correct `PIA-PIA-RRM-PIAM` Renewal-Maintenance asset, created via `initiate-renewal` off that asset. Ensure: (i) the asset is lifecycle-clean with `Renewal Pricing Type` = Last Negotiated/LTP and a populated `AssetActionSource`; (ii) `ContributorScope` on the derived element admits **non-transactional/asset** lookups; (iii) discovery + pricing share one context; (iv) `Map Products` maps that asset's product → the derived product. This is the exact configuration of the one line that already commits 67.38 — i.e., **the org has a working reference instance.** Every link in this chain is documented; only the asset→`Contributing*` field mapping is inferred and must be confirmed against the live element.

**Option B — Fix the wrong-asset wiring ($0 lines). `[WELL SUPPORTED, subset of A]`**
The $0 lines point `SourceAsset` at the owned New-Maintenance `PIA-PIA-RNM-PIAMBK` asset. Re-point the renewal to the Renewal-Maintenance asset (or fix whatever process stamps the wrong asset). Documented role of `SourceAssetId` makes this a data/wiring fix, not a code fix. **Verify whether `initiate-renewal` is setting `SourceAssetId` automatically or whether the org is hand-creating QuoteActions** — the latter would explain both the wrong-asset and the no-QuoteAction populations.

**Option C — Seed the asset/QuoteAction for "no-QuoteAction" lines. `[WELL SUPPORTED]`**
The 60.64-fossil lines bypassed renewal-from-asset entirely. The supported answer is **not** to write `NetUnitPrice` — it is to route these through `initiate-renewal` so a `QuoteAction`/`SourceAsset` exists for Asset Discovery to follow. A "bare derived QLI" with no renewal action is not a documented derived-renewal pricing path.

**Option D — Sanctioned rep net-override at price time. `[DOCUMENTED, but a different lever]`**
*"Sales reps can apply an additional discount on top of the calculated price uplift, overriding the net unit price"* ([Help — CPI & price uplifts](https://help.salesforce.com/s/articleView?id=ind.qocal_consumer_price_index_and_price_uplifts.htm&language=en_US&type=5)). This is an explicitly supported write to `NetUnitPrice` — but it happens **at renewal/price time through the engine**, layered on a computed uplift, *not* as a post-settlement Apex DML. It is the sanctioned fallback **only if** the asset/AAS path genuinely cannot be made to resolve, and the docs do not confirm it applies to a *derived* line specifically (open question below).

**Not supported — force-writing `NetUnitPrice` post-settlement.** Our COLAUpliftHandler/posthook/`RenewalMaintenancePricingService` DML/`updateContextAttributes` approach has **no documentation support** for moving a settled derived line and is contradicted by the engine-ownership model. `isSuccess=true` with no value change is the expected outcome, not a bug to be debugged in the writer — the writer is operating on the wrong layer.

## Gaps — where official docs are silent (and what it implies)

1. **Native element name & input mapping.** `[inferred]` Docs never name `DerivedProductsRenewals` nor state that `ContributingId`/`ContributingProduct` can be an **Asset/AssetActionSource** vs a sibling quote line. The whole "asset is the contributor" join rests on combining two documented mechanisms. **→ Confirm via the live element's input bindings + a FINEST reprice trace before committing to Option A.** *(This also ties to SC-3372's native `DerivedPricingDataRetrieval` finding — verify the renewal path is actually fed by a discovery procedure sharing the Rev_Mgmt context, not a hardcoded native discovery the design says to remove.)*

2. **Empty-contributor behavior.** `[inferred]` Docs say the formula operates on contributor inputs but **never spell out** whether zero contributors yields $0, null, or "leave prior value." Our org shows **both** ($0 for wrong-asset, 60.64-retain for no-QuoteAction). **→ This behavioral split is a FINEST-log fact, not a doc fact** — and the difference matters for which population needs which fix.

3. **Wrong-product asset → $0 vs List fallback.** `[inferred]` Docs give the LTP-present formula and a documented `List Price` `Renewal Pricing Type` fallback, but **not** what happens when the resolved asset is the wrong product with no usable AAS. Our observed $0 suggests the live element's fallback is not wired to List. **→ Verify the element's fallback wiring; a List fallback might be a safer interim than $0.**

4. **Exact `ContributorScope` values & `Map Products` product-equality.** `[inferred]` The picklist semantics and whether `Map Products` requires the contributor's `Product2` to exactly equal the renewed asset's `Product2` (which would formally explain PIAMBK→$0) did not render. **→ Confirm in the org; this is the crisp test for the $0 root cause.**

5. **Asset field API names.** `[inferred]` `Renewal Pricing Type` / `Pricing Source` / LTP picklist values came from help-page snippets, not the rendered Asset object reference. **→ Retrieve the live Asset describe in UAT and inspect the actual values on the PIAM vs PIAMBK assets.**

6. **Read-only semantics on a settled derived QLI.** `[inferred]` Docs frame `NetUnitPrice` as engine-owned/computed but don't publish a hard platform-tier write-protection flag. **→ Confirm from RLM field metadata; our DML-insert + reprice-write observations are the current evidence.**

**Implication for fix vs workaround:** The **supported fix** is unambiguously to repair the **contributor** (Options A/B/C — make the correct prior asset present, lifecycle-clean, and in-scope). The **rep override** (D) is a documented but different lever and unconfirmed for derived lines. **Post-settlement `NetUnitPrice` writes are neither a fix nor a sanctioned workaround** — they are the wrong layer. The one line already committing 67.38 is your ground-truth template: replicate *its* QuoteAction/SourceAsset/asset-LTP configuration across the failing population.
