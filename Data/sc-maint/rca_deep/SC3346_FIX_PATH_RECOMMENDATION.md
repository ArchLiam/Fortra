# SC-3346 Renewal-Maintenance Commit — Fix Path Recommendation (FortraUAT, 2026-06-14)

## Context in one paragraph (reprice-time fixes refuted; only born-net or de-derive remain)

Renewal-maintenance lines for the BoKS RRM SKU (Product `01tWC00000DD1buYAD`, "Powertech Identity & Access Manager (BoKS)-RenewalMaintenance") commit the **wrong COLA net** — fossilized values of 60.64, 54.58, or $0 — instead of the correct 67.38. Every reprice-time heal we tried is now **proven dead**: lever-d's `RenMaintCOLANet` AssignmentElement (writing `COLACalculatedPrice__c`→`NetUnitPrice`) did not move the fossil in the authorized 2026-06-14 test, and the element name `RenMaintCOLA` never even appears in any canary FINEST log, so we can't prove it fired — only that nothing moved. `PartnerNetPricePosthook v1.5` is correct (it closes the pre-v1.5 ×0.90 re-discount) but its corrective `NetUnitPrice` write hits the same dead node. That leaves exactly two structural candidates: **born-net at creation** (give the line a `Type='Renew'` QuoteAction so it forms correct in the create-pricing cycle) and **de-derive** (price RRM via a non-derived PBE). De-derive is refuted below; born-net is proven by the control line. This doc lands born-net as the primary fix with concrete, implementable code, plus the honest open questions that gate deploy.

## The lock mechanism — settled, in plain terms (why NetUnitPrice can't be rewritten; what specifically unlocks it)

The lock is **"does-not-run," not platform immutability**. On a derived renewal-maint line (`ItemIsDerived__std=true`, via PBE `01uWC000006XPPBYA4` `IsDerived=true`), the **only** `resultIncluded=true` element authorized to (re)write `NetUnitPrice` is the native DerivedPricing action `DerivedProductsRenewals` (V14 file lines 71913–72040). That action is **contributor-keyed by construction** — every input is a `Contributor*` parameter (`ContributingNetUnitPrice=ContributorUnitPrice`, `ContributingId=Contributor`, `ContributingProduct=ContributorProduct`, etc.). A line with **no contributor entry is simply skipped**, so its `NetUnitPrice` is never recomputed and the persisted fossil is retained.

The smoking gun is the canary FINEST log (line `0QLWC000003e2Sn4AI`, 16 context dumps): the writable **INPUT** `InputUnitPrice` reaches 67.38 and the custom field `COLACalculatedPrice__c` reaches 67.38, but the **OUTPUT** `NetUnitPrice` is stuck at 60.64 across all 16 dumps — and there are **zero `<lineId>cli` contributor keys** anywhere in the log for that line. The COLA net *is* computed (`DerivedPricingRenewals`, RI=**false**, line 71764, fires for fossils too because its gate has no contributor predicate) but it lives in-engine only and is never committed. By contrast, in the regression order the derived lines **are** keyed in the contributor map and one commits a real `NetUnitPrice=325.0`.

**What specifically unlocks it:** a `Type='Renew'` QuoteAction on the line whose `SourceAsset` is a maintenance asset. That QuoteAction does two things at insert: (a) `COLAUpliftHandler.handleBeforeInsert` prices the line **born-net** (`COLA_Source='CMDT Lookup'`), and (b) the asset becomes the **contributor** the native `DerivedProductsRenewals` action keeps re-deriving. The control line `0QLWC000003dEW24AM` (NUP=67.38) and the fossil `0QLWC000003e2Sn4AI` (NUP=60.64) are **field-for-field identical** — same `Base_Price__c=71`, same `Source_List_Price__c=355`, same `COLACalculatedPrice__c=67.38`, **same derived PBE** — differing **only in `QuoteActionId`**. That single difference is the entire mechanism.

One honesty caveat on the micro-mechanism: we have **not byte-proven** whether a reprice-time `AssignmentElement` write to `NetUnitPrice` is silently discarded vs. the engine reloading the persisted value after each element on a contributor-less node. The *outcome* is decisive (inputs reach 67.38, output stays 60.64) and the fix conclusion is independent of which micro-mechanism is true.

## Fix Path A — Born-net via Apex after-insert QuoteAction stamper (PRIMARY)

**What changes.** A new Apex class (e.g. `RenewalQuoteActionStamp`), invoked from `QuoteLineItemTrigger` after-insert, mints a `Type='Renew'` QuoteAction pointed at the customer's owned maintenance asset and links it to each configurator-auto-added RRM renewal-maintenance line that was born with `QuoteActionId=null`. On the next reprice the line is now a **priced node with a contributor**, so the native `DerivedProductsRenewals` commits `NetUnitPrice=67.38`.

**Concrete steps.**
1. New class `RenewalQuoteActionStamp`, called from `QuoteLineItemTrigger` after-insert, **after** the existing `RenewalQuoteLineHandler.enqueueCarryoverCleanup` call (`QuoteLineItemTrigger.trigger` L11–13).
2. Filter `Trigger.new` to lines where `Product2.Fortra_Product_Type__c='Renewal Maintenance'` AND `QuoteActionId==null` AND the parent quote is a renewal (`Quote.OriginalActionType='Renew'` OR `Quote_Type__c='Renewal'`; reuse `QuoteRenewalTypeHandler.ORIGINAL_ACTION_RENEW` / `QUOTE_TYPE_RENEWAL`).
3. Resolve the renewal-source asset on the quote's Account (single bulk query): **prefer** the RNM (`Fortra_Product_Type__c='New Maintenance'`) asset sharing the line product's `Solution_Category__c`; **fall back** to the Perpetual license asset; require `Price` not null.
4. Upsert one `QuoteAction(QuoteId=line.QuoteId, Type='Renew', SourceAssetId=resolvedAsset.Id)` per (quote, asset) pair (reuse an existing matching Renew QA, as the control quote has two), then set `QLI.QuoteActionId` and update. **Bulkify** (one asset query, one DML batch) and **guard recursion** on the re-entrant QLI update.
5. Validate on a fresh canary: assert `QuoteActionId` populated → Net flips to 67.38 with `COLA_Source='CMDT Lookup'`.

**Why it works (tie to the control line).** The control `0QLWC000003dEW24AM` commits 67.38 on the *same derived PBE* solely because it carries QuoteAction `7ocWC00000u7yf8YAA` (`Type='Renew'`, `SourceAssetId=02iWC000008GKPaYAO`). Five independent probes converge: `QuoteActionId` presence is the **sole discriminator**. The 67.38 is recomputed by the procedure from the prehook-seeded `Base_Price__c=71` (provenance-independent), **not** from the asset's price — so a synthesized QA pointed at the customer's owned **RNM** asset (e.g. canary's `02iWC000008DmS1YAK`, Price 62.48, same `Solution_Category__c`, same 7.85% CMDT rule) still yields 67.38. The mechanically-proven precedent exists in `COLAUpliftTest.cls` (L1884/L2463/L2518: `insert new QuoteAction(QuoteId=q.Id, Type='Renew', SourceAssetId=asset.Id)` then a QLI carrying that `QuoteActionId`, producing born-net COLA). `QuoteLineItem.QuoteActionId` is `createable=true` and `updateable=true`; `QuoteAction` requires only `QuoteId`+`Type` to insert.

**Risk.** (1) **RLM/Subscription-Mgmt Quote-DML lock** is the single biggest unknown — QuoteAction/QLI DML inside the managed Place-Quote persist may be blocked at the platform tier; if so, the stamp must move earlier into the renewal-creation flow/Queueable or a dedicated invocable in `Fortra RCA Renewal Enhancement`, so the QA pre-exists when the PCR auto-adds the line. (2) An Apex-minted QA **not** produced by `initiateRenewal` could interact with native RCA renewal/amendment lifecycle or QA-driven flows (`Fortra_RCA_Renewal_Enhancement` reads `Get_QuoteAction.Type`) in untested ways. (3) Pointing at the RNM asset (62.48) vs. an RRM asset (60.64) shifts the **audit** fields `UnitPrice`/`Pre_COLA_Price__c` (handler writes `assetPrice`) though **not** the committed Net (procedure recomputes from `Base_Price__c=71`) — cosmetic but should be reviewed. (4) Deterministic source-asset selection is required when an account owns multiple BoKS NewMaint/Perpetual assets. (5) `RenewalQuoteLineHandler` deletes the carryover RNM/Perpetual *lines* after-insert via Queueable — the QA references the **asset**, not the line, so deletion should be safe, but ordering must be confirmed. (6) Re-entrant QLI update must not let `COLAUpliftHandler.handleBeforeUpdate` misclassify the freshly born line.

**Blast radius.** Code-only, one new class plus a one-line trigger hook. No PBE/procedure/decision-table mutation. Touches Nir's renewal architecture surface (QuoteAction lifecycle) and is adjacent to Marc's `COLAUpliftHandler`. Regression guards: control 67.38, NB-derived 71, perpetual 301.75, FIM 462.

**Owner ask.** Nir: approve minting QuoteActions outside `initiateRenewal`; confirm the source-asset selection rule (prefer RNM same `Solution_Category__c`, else Perpetual); confirm forward-only with fossils remediated separately. Marc: sign off on the `COLAUpliftHandler` interaction (or, in the variant below, on extending the handler directly).

**New lines vs. existing fossils.** Heals **NEW** lines only. The 5 Draft fossils + Accepted quote `00781068` + Order `00095475` (Workday COM003) + Asset `02iWC000008GKPaYAO` are **not** healed — `NetUnitPrice` is locked on the settled QA-less derived node and no reprice-time write moves it. See the fossil-remediation section.

## Fix Path B — Born-net via extending COLAUpliftHandler.handleBeforeInsert to synthesize the QuoteAction (PRIMARY VARIANT / least-invasive seam)

**What changes.** Instead of a separate after-insert stamper (Path A), extend the **already-wired** `COLAUpliftHandler.handleBeforeInsert` (called in `QuoteLineItemTrigger` before-insert, L26–27) so that when it sees an auto-added renewal-maint line with `QuoteActionId==null` on a renewal quote, it **synthesizes** a `Type='Renew'` QuoteAction (`QuoteId=qli.QuoteId`, `SourceAssetId=`owned RNM asset for that account/Solution_Category) and sets `qli.QuoteActionId` **in the same before-insert pass** — so the line is born a priced "Renew" node and the procedure commits `NetUnitPrice` in the very first create-pricing cycle, with no second reprice needed.

**Concrete steps.**
1. In `handleBeforeInsert`, add a branch *before* the early-return at L29–31: for lines with `Fortra_Product_Type__c='Renewal Maintenance'`, `QuoteActionId==null`, on a renewal quote, resolve the owned RNM asset (same `Solution_Category__c`) and synthesize the QA.
2. Insert the QA first (QuoteId is available in before-insert), then back-reference `qli.QuoteActionId = qa.Id` on the in-memory before-insert row so `populateCOLAFields` runs in the same pass.
3. Keep the existing born-net logic untouched for lines that already carry a QuoteActionId.

**Why it works (tie to the control line).** Same mechanism as Path A — the discriminator is QuoteAction presence at insert. The advantage is it reuses the **single cleanest extension seam**: `handleBeforeInsert` already sees the auto-added line and already bails *only* because `QuoteActionId` is null (L29–31 early-return, L34–40 `Type='Renew'` filter, L280–282 skip). Synthesizing the QA in-place means the line forms correct on first save, avoiding a separate reprice round-trip.

**Risk.** Largely the same as Path A, with two differences: (1) **DML inside before-insert** of the managed PST is the higher-risk placement for the RLM Quote-DML lock — a `QuoteAction` insert mid-before-insert-trigger is exactly the kind of nested DML most likely to be blocked, so this variant is **more** exposed to the lock than Path A's after-insert placement. (2) It puts renewal-architecture logic inside Marc's COLA handler, blurring ownership; Nir + Marc must jointly own. **Hard blocker regardless of variant:** the `COLAUpliftTest` `buildOverrideMap` 41-error drift must be fixed before any procedure-side validate — it's a prod-cutover blocker independent of this fix.

**Blast radius.** Code-only, one handler. Same regression guards. Slightly more invasive to Marc's surface than Path A.

**Owner ask.** Marc + Nir jointly: approve handler-level QA synthesis vs. the separate-class approach (Path A).

**New lines vs. existing fossils.** Same as Path A — **NEW lines only**.

## Fix Path C — De-derive the RRM PBE (REFUTED; do not pursue)

**Brief.** De-derive is **refuted by the data**: the control line commits the correct COLA net 67.38 **on the derived PBE** `01uWC000006XPPBYA4` (`IsDerived=true`), proving `IsDerived` is neither the lock nor necessary for a clean commit. The blocker is the missing born-net QuoteAction, not the derive flag. Beyond being refuted, de-derive is high-risk: the license→maintenance derive is a **~950-PBE Renewal-Maintenance class pattern**, and the **939 New-Maintenance** SKUs price *correctly* (71) via the *identical* mechanism — a class-wide de-derive risks regressing them, while a BoKS-only de-derive fixes 1 of 950 SKUs and doesn't generalize. The derive is also the **seed** for `Source_List_Price__c=355`/`Base_Price__c=71`; severing the PBEDP without a replacement seed nulls the COLA base and the prehook bails (`Base_Price__c>0` gate), zeroing the line. Finally, the only existing **non-derived** RRM PBEs sit on the **Term Based - Annual** selling model, but the broken lines use **One Time** — there's no non-derived One-Time fallback to land on. **Recommendation: drop de-derive.** (One adjacent idea worth a *separate* low-priority probe, not a fix here: whether the AutoAdd PCR could target the existing non-derived Term-Based PBE — but that's a selling-model change, not a de-derive.)

## Existing-fossil remediation — what heals the wrong lines, and the Accepted-line caveat

**No reprice-time change heals existing fossils.** Attaching a QuoteAction to an *existing* settled line and repricing does **not** work: the update-trigger context (`handleBeforeUpdate`, L55–130) never re-stamps `UnitPrice` from the QuoteAction (it only handles user COLA% override recalcs), and `NetUnitPrice` is locked on the settled QA-null derived node. The handler never writes `NetUnitPrice` directly anyway — it writes `UnitPrice` *before* the procedure runs, so the correction must happen at insert.

**Therefore: re-create born-correct.** For each Draft fossil (`0QLWC000003e2Sn4AI` net 60.64; `0QLWC000003ck6X4AQ`, `0QLWC000003cN584AE` net $0; `0QLWC000003eMph4AE`, `0QLWC000003cy334AA` net 54.58): **delete** the QA-less fossil line and **re-add** the RRM renewal line on the same (Draft) quote with a `Type='Renew'` QuoteAction attached **at insert** so it is born-net. Do **not** set `QuoteActionId` on the existing line and reprice — it silently fails to move `NetUnitPrice` while `COLACalculatedPrice__c`/`InputUnitPrice` update, producing a **false positive** in dashboards.

**Two open caveats on remediation.** (1) The **RLM Quote-DML lock** may block raw delete/re-add of fossil QLIs; if so, re-creation must route through the supported renewal/configurator flow, not raw QLI DML — this was a read-only probe and was **not** verified. (2) For the two **$0 fossils**, confirm the $0 is purely QA-less provenance vs. an additional PBEDP/contributor gap on PBE `01uWC000006XPPBYA4` (direct/reverse PBEDP lookups returned no rows in the probe; verify the `182WC` PBEDP family resolves the contributor before re-create).

**Accepted-line caveat — DO NOT TOUCH.** The Accepted quote `00781068` / line `0QLWC000003dAaT4AU` must not be modified. Downstream remediation of Order `00095475` (synced to Workday COM003) and Asset `02iWC000008GKPaYAO` (Price 60.64) is a **separate owner-gated (Nir) workstream**, not part of the forward fix. Keep `PartnerNetPricePosthook v1.5` in place as the floor regardless — it is correct and orthogonal, and closes the pre-v1.5 partner re-discount.

## RECOMMENDATION — primary + fallback

Path A is preferred over Path B because the **after-insert** DML placement is materially less exposed to the RLM Quote-DML lock than mid-before-insert DML, and it keeps renewal-architecture logic out of Marc's COLA handler (cleaner ownership boundary). Treat **Path B as the fallback** if owners prefer single-pass born-net with no second reprice and accept the higher lock exposure + shared ownership.

## ⭐ RMPS-via-V27 zero-code check — RUN 2026-06-14 → ❌ NO-OP (born-net Path A confirmed as the fix)

The "highest-value unrun test" (would the already-wired `RenewalMaintenancePricingService` heal the fossil for free?) was executed. **Result: it does not.**

- Active flow `Fortra_Quote_Reprice` confirmed = **V27**, AutoLaunchedFlow, input `QuoteId`, RMPS wired (4 refs, passes `contextInstanceId`).
- Invoked on the canary via anon Apex: `new Flow.Interview.Fortra_Quote_Reprice(new Map<String,Object>{'QuoteId'=>'0Q0WC0000038aXd0AI'}).start();`

**Significance:** this is the **third independent** reprice-time `NetUnitPrice` write proven to no-op on a settled derived node (posthook v1.5 → lever-d procedure committer → RMPS-via-V27) — and the **cleanest proof**: a direct `updateContextAttributes({NetUnitPrice: 67.38})` returns `isSuccess=true` while the committed value is silently discarded. The "lock" is now byte-proven: **no reprice-time write of any kind can set `NetUnitPrice` on a settled derived node.** → **Born-net (Fix Path A) is the fix; there is no zero-code shortcut.** Evidence: `Data/sc-maint/rca_deep/fixpath/run/rmps_v27.log`.
