# SC-845: Quote Document Generation + DocuSign

## Summary

End-to-end "Generate Document" experience on the Quote record: launches an OmniScript that builds an English quote PDF from a `DocumentTemplate`, displays a preview, and (optionally) sends it for signature via DocuSign.

User flow: **Quote → Generate Document button → OmniScript modal (preview) → Send Quote → DocuSign envelope created.**

## Post-deployment steps

Run these in order. Steps 4–7 are the ones that bit us in UAT.

### 1. Verify External Credentials (DocuSign)

- Setup → Named Credentials → External Credentials
- Confirm `DocuSign-DocuSignPrincipal` exists and the principal is configured with valid DocuSign integration credentials for the target org.

### 2. Upload the DocumentTemplate

- Setup → Document Generation → Document Templates
- Upload `Fortra Quote Consolidated EN.docx`
- Set **Status = Active**
- The template `Name` must match the value `Quote_GenerateDoc_English_4` filters on (`templateName` input param). Don't rename without updating the IP.

### 3. Verify the OmniScript and IPs are Active

- OmniStudio → OmniScripts → `DocumentGeneration_Quote_English_3` → **Activate**
- OmniStudio → Integration Procedures → `Quote_GenerateDoc_English_4` and `Quote_SendDocuSignEnvelope_Procedure_1` → **Activate**

### 4. Share the DocumentTemplate file with `DocGen Template Users`

- Open the template's underlying file (Files tab)
- Sharing Settings → add the **DocGen Template Users** public group with **Viewer** access
- This is the actual gate for non-admin / non-owner users. Skipping this causes the OmniScript to throw "List has no rows for assignment to SObject" with no useful error context.

### 5. Assign Permission Set Licenses

For every user who will generate documents:

- `OmniStudio` (DeveloperName: `OmniStudioDesigner`)
- `DocGen Designer` (DeveloperName: `DocGenDesignerPsl`)

### 6. Assign Permission Sets

For every user who will generate documents:

- `Omnistudio` (runtime PS — **not** the same as the PSL above)
- `DocuSign_API_Access` (only required if they'll also send for signature)
- A PS that grants read on `Places__c`, `Hardware__c`, `QuoteLineGroup`, `QuoteLineItem`. In Fortra UAT this is `Operations Team Access`. Confirm the equivalent in your prod org.
- `DocGen User` — **not strictly required** based on UAT evidence (Liam generates docs without it), but recommended for least-privilege users who don't have `View All Records and Fields` or `System Admin Full`. May unlock access to `DocumentGenerationProcess` and related runtime objects. Test with a non-admin user before deciding.

### 7. Add users to `DocGen Template Users` public group

- Setup → Public Groups → DocGen Template Users → add each doc-generating user
- Without this, the user gets "List has no rows..." even with all PSes correct, because the underlying template file is invisible to them.

### 8. Smoke test as a non-admin

- Log in as a freshly-provisioned user (NOT as a sysadmin / NOT as the template's uploader — those bypass the sharing layer and hide bugs)
- Open a Quote → Generate Document → verify PDF preview renders → Send Quote → verify DocuSign envelope created

## Known gotchas

- **Sysadmin doesn't bypass file sharing.** A user can have System Administrator profile + every PS in the org and still fail Generate Document if they're not in `DocGen Template Users` (or aren't the file owner). The DocGen runtime returns a generic "List has no rows" error that misleads triage toward permission sets.
- **The "Scriot" typo** in `docGenOmniScriotWrapperLWC` is intentional now (rename = breaking change to deployed components). Leave it.
- **`DocuSign_API_Access` field perms target `OrderItem`**, not `QuoteLineItem`. The permission set name suggests broad DocGen access; it doesn't grant any DocGen-relevant query permission.
- **`DocGen User` PS is misleadingly named.** Joe had it assigned from day one and DocGen still failed; Liam doesn't have it and DocGen works. The PSLs (`OmniStudio` + `DocGen Designer`) are what actually license the DocGen runtime — the `DocGen User` PS is supplemental at best.
- **Template file lives on `DocumentTemplateVersion`**, not `DocumentTemplate`. SOQL'ing `ContentDocumentLink WHERE LinkedEntityId = <DocumentTemplate.Id>` returns 0 rows even for the file owner — don't use that as a diagnostic.

## Deployment order (if running fresh)

`

```
1. Static resources, classes, LWC, permission sets, public groups (parallel-safe)
2. DataRaptors (parallel-safe within group)
3. Integration Procedures (depend on DataRaptors)
4. OmniScript (depends on IPs)
5. Manual: upload DocumentTemplate, activate OmniScript/IPs, share file, assign PSL/PS, populate group
```
