### 1d. PRIOR REGRESSIONS → LESSONS THE PLAN MUST STRUCTURALLY PREVENT

Treat each as a failure mode the target architecture and wave plan must make **impossible or loudly detectable.** **Reference each by name in your risk register.** This consolidated register is the safety spine of the plan.

1. **Step-deletion silently breaks a whole line-class.** The TermDefined Proration element (`ProrationMultiplier → PricingTermCount`) was dropped in the V11→V12 rebuild → all TermDefined lines got `PricingTermCount = null` through V14/V20, cascading into convert (SC-3406), activate (SC-3411), no-Assets (SC-3415). `PricingTermCount` is **engine-only writeable — no Apex/flow backstop.** → _Characterize every line-class (One-Time / TermDefined / Evergreen / renewal-derived) before and after any step change; note engine-only fields have no safety net._
2. **Version "merge" silently drops deltas.** Activating V20 on the false claim "everything from V16 moved over" lost the TermDefined proration sub-tree, regressed the derived formula 7-tier→3-tier, and dropped two `IsNotNull` aggregate guards = "COLA not working." → _Treat any version activation as a merge that can drop deltas. 3. **Performance edits that delete correctness checks.** The Workday line-type flow V9 rewrote a subsplit decision into an always-true self-comparison while dropping a SOQL for governor relief → every non-services line stamped FIXED AMOUNT BILLING ONLY, org-wide Workday failure. → _Bulkify checks; never delete them for governor relief; verify branch logic empirically before/after the exact deploy timestamp._
4. **Inline rate constants drift and hide gaps.** `DerivedPricingFormula` hard-coded 3 of 7 maintenance tiers → the other 4 hit an x0 fallback → $0 on 1,031+ live rows; the in-place fix then **oscillated** (clobbered by a co-owner republish, re-applied). → _Prefer CMDT lookups over inline constants; a lone in-place fix on a co-owned version ping-pongs._
5. **In-place edit without context resync = org-wide outage.** A live V9 edit added steps reading `Prior_*_Discount__c` without re-syncing `SalesTransactionContextExt_v2` (Order-side mapping blank) → "Specify the contextDefinitionName" gack on every Order Reprice/convert. V16 later referenced `Pre_Partner_Price__c` on the Order side where it existed only on `QuoteLineItem` → whole-context fetch hard-fail on Orders.
6. **Silent reset-to-list / stale-context non-idempotency (SC-3390).** A tiered quantity edit needed "Update Price" clicked twice; the first click priced a stale snapshot / silently reset to list with no error. → _Hooks must surface a no-match, not swallow it; reprice must be idempotent (first-click == second-click)._
7. **Null-unsafe filter predicates (K-01 / SC-3441 / F-12).** Cancel/amend-remove lines (`NetUnitPrice` null) hard-aborted reprice because `StampBaseFilter`'s `NetUnitPrice > 0` isn't null-safe (SF-BRE-00004); only **3 of 6** instances were patched first because the step is duplicated per-version. → _Null-safety on filter predicates is load-bearing for cancel/credit/amend; a partial fix leaves copies unpatched — count instances on the exact active version._
8. **Refactor a hook, orphan its test (SC-3346).** `COLAUpliftPrehook` was rearchitected (list-passing seams → `ctxInstanceId` flow) but `COLAUpliftTest` wasn't → 41 compile errors, 0% solo coverage, un-promotable to prod. → _Characterization tests land FIRST and are re-seamed with every hook change — this is why Wave 0 builds the harness before any change._
9. **One in-place edit regresses an unrelated combination (F-09).** An in-place V21 step edit double-FX'd non-USD partner net (corporate 0.92 × hardcoded 0.9346, ~8% under) — a scenario that had PASSED earlier the same day. → _Every in-place pricing edit requires a full golden-scenario re-validation; one step change can silently regress a currency/partner combo you weren't touching._

**Overarching lesson baked into the plan's shape:** separate **non-behavioral** work (rename, document, add tests, remove provably-unreferenced code, extract-method with identical output) from **behavioral** work (consolidating two live implementations, reordering, altering a calculation). They live in **separate, separately-gated waves** and are never mixed.

### 4f. Known fragilities to characterize (not fix)

Static recursion guards (`isProcessing`/`isUpdating`) in every hook — on re-entry the guard returns SUCCESS and the hook **silently no-ops**; a guard left true after a mid-`execute()` exception (no `try/finally` reset on all paths) is exactly the silent-green regression the plan must prevent. `execute()` is **not unit-testable** (managed `RevSignaling.TransactionRequest/TransactionResponse` have no public constructor; QLIA needs `Database.insertImmediate()` and doesn't persist in test context) — coverage today is only `@TestVisible` seams via `PricingPrehookTestFixtures`; real validation is manual in-org reprice. Hardcoded maps/magic values (`CurrencySelectionService` country map, hardware defaults, the 10-attribute description list, inline 7-tier rates, V21 FX 0.9346). Null-guard gaps on context Decimals (SC-3393, E-04). Uneven `@InvocableMethod` bulkification (SC-3366 SOQL:101, SC-3447 Power CPU). Formula-STRING currency conversion (malformed/stale → silent mispricing). Silent reset-to-list on no-match (SC-3390).

- **Retrieve-live-first (§1a), then read.** Prefer live-retrieved bodies for every in-scope class and the active ESD version before any claim. Concrete, provably read-only mechanisms:

    - **Retrieve the ESD read-only:** MDAPI retrieve with **API 67.0 + `--metadata-dir`** (v66 fails on dataType). This is a read; do not follow it with any deploy.
    - **Confirm each discovery procedure's live-vs-legacy wiring (read-only):** grep the reprice flow(s) (e.g. `Fortra_Quote_Reprice`) and context/ProcedurePlan records for references to `Salesforce_Pricing_Discovery_Procedure` / `Salesforce_Default_Pricing_Discovery_Procedure(_v2)` / `Product_Discovery_Pricing_Procedure`; a procedure with no live flow/context reference is a legacy candidate. Resolve this rather than deferring the whole question to Open Questions; escalate only what the read-only checks genuinely can't settle.
- **Freshness / snapshot protocol (defends a multi-hour run against minute-to-minute co-owned edits):** **timestamp every live retrieve.** Immediately before writing the executive summary / handing off, **re-verify the active `ExpressionSetDefinitionVersion` and the top-risk class bodies** (`PartnerNetPricePosthook`, the partner V1/V2 pair, COLA prehook/handler). If any changed since first retrieve, note the delta and re-tag affected findings.
- **Parallelize with subagents — but bounded.** Fan out **≤ 5 lanes**, e.g.: (1) hook→service→handler→invocable→batch/queueable call graph + context-node/boundary-MDT reads/writes; (2) duplication/dead-code census with runtime-wiring proof; (3) waterfall order across the two metadata layers (ProcedurePlan prehooks + ESD steps + posthook); (4) reconcile the ~22 versions by label+function on the ACTIVE version only; (5) boundary-interface catalog. **Depth caps to avoid rabbit-holes:** the in-scope class census goes to full method-level depth; the ~22-version diff is **active-version-deep only** (do not fully diff all 22 — reconcile inactive ones by label+function summary); the LKG/boundary lanes are **map-only, do NOT enumerate** (family + entry point + one representative). Each subagent returns `file:line` evidence and CONFIRMED/CORRECTED/UNVERIFIED tags. Reconcile their outputs yourself.
- **Cite evidence:** every non-obvious claim carries a `file:line` or live-retrieve reference. A claim without evidence is an **open question, not a finding.** Where a memory/KB/fix-spec claim conflicts with live evidence, prefer live and note the correction.
- **Traceability mandate:** **do not propose a single roadmap item that isn't traceable to a numbered current-state inventory finding.** The plan is an auditable chain from evidence → debt → wave.
- **Match procedure steps by label + function, NEVER by `<name>`** — integer suffixes are version-specific and produce both false-positive and false-negative diffs.
- **Stay read-only.** Retrieves and diffs only; no deploys, DML, reprice, or validate-only. Everything under `Data/sc<ticket>/`.
- Where you cannot verify something read-only, say so and put it in **Open Questions** with an owner — do not guess.

## 7. VERIFICATION / GOLDEN-SCENARIO STRATEGY (design it; do NOT execute it)

The only trustworthy behavioral check in this org is **repricing and diffing outputs** — static reasoning is necessary but never sufficient, and **unit tests alone are not a valid oracle** (SC-3346 tests passed against stale list-API context while live pricing broke). Design a regression net the eventual execution phase will run; hand it off as a ready-made acceptance gate.

- **First, locate and cite the existing harness.** Confirm read-only whether `Data/pricing-v21-validation` (the ~104-scenario harness, run3 2026-06-30: 69 pass / 13 fail / 22 blocked, 13 tracked defects) actually exists at that path before declaring it the model. If it exists, cite it and its scenarios; **if it does not, say so and specify the matrix from scratch** — do not assume it.
- **RE-BASELINE before Wave 0 relies on it.** The recorded run3 counts may be stale by execution time; instruct re-running the baseline against current live state rather than trusting the recorded numbers as the regression oracle. No currently-passing scenario may regress; the known-failing set is tracked **separately** so a refactor is never credited with "accidentally fixing" pricing. (Fortra truth: no evergreen catalog / no contracted pricing exist → those scenarios are N/A by design, not blocked.)
- **Golden pricing-scenario matrix** as primary oracle: new vs renewal; one-time / subscription / perpetual / maintenance; partner net; regional / multicurrency; tiered / volume; hardware / Power. Snapshot **`NetUnitPrice`, `TotalPrice`, `PricingTermCount`, From/To dates, Workday line-type, Asset count** per scenario.
- **Reprice BOTH a Quote and an Order** (shared context; dual-object failure is the #1 silent regression). Every scenario is driven through the **managed reprice runtime** (`POST /connect/rev/sales-transaction/actions/place`), never direct DML (RLM lock).
- **Parallel-run equivalence** for every duplicate consolidation (compute retiring + surviving side-by-side across the full matrix; assert equality before retirement).
- **Idempotency:** reprice each scenario twice (first-click / second-click); assert stable output (guards SC-3390).
- **Null-path scenarios explicit:** null `NetUnitPrice`, null US-line net, missing optional context fields, null `PricingTermCount` → documented defaults, not `$0` or throws (guards SC-3393 / SC-3441 / K-01 / F-12).
- **Governor/perf assertions:** SOQL + CPU counts on 15+-line and high-qty Power scenarios must not regress (guards SC-3366 / SC-3447).
- **Downstream proxies unchanged:** Workday line-type stamping, Assetize Asset count on activation, Order-activation term fields (EndDate/PTC).
- **Boundary contract tests:** assert hooks still read the same COLA / regional / FX / tier MDT and PBE values after refactor — proving the out-of-scope seam was undisturbed.
- **Platform reality that shapes this:** `execute()` is not directly unit-testable, so the net is **`@TestVisible` seam tests (`PricingPrehookTestFixtures`) + headless Force-reprice** over the fixed matrix — **not** raw code-coverage %. Declare the characterization/golden tests captured at plan time as the **acceptance gate for the eventual execution phase.**
